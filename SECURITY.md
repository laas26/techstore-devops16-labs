# 🛡️ Política de Segurança (Security Policy)

## Versões Suportadas

Ativamente mantemos e corrigimos falhas de segurança apenas na versão de desenvolvimento atual. Se você estiver rodando uma versão antiga, atualize seu ambiente local imediatamente.

| Versão | Suportado (Correções) |
| ------- | -------------------- |
| `develop` (Atual) | ✅ Sim |
| `main` | 🔄 Apenas correções críticas |
| Outras | ❌ Não |

## Como Reportar uma Vulnerabilidade

**Não abra "Issues" ou comentários públicos para relatar bugs de segurança.** 

Se você acredita ter encontrado uma vulnerabilidade no sistema da **TechStore**, envie um relatório privado para a equipe de **DevSecOps** da nossa turma. Adotamos o processo de **Divulgação Responsável** para garantir que a falha seja corrigida antes de se tornar pública.

* **Canal de Envio Privado:** `[Link do WhatsApp do grupo de segurança ou DM do Discord]`

---

## ⚙️ Nosso Processo

O fluxo é gerenciado pela equipe de segurança em parceria com os desenvolvedores do projeto:

1. **Aviso de Recebimento:** O squad de DevSecOps recebe o alerta (via GitLab ou mensagem privada) e notifica os líderes de Front e Back sobre o ponto de atenção no código.
2. **Análise Conjunta:** A equipe de DevSecOps lidera os testes de validação, compartilhando os aprendizados com os desenvolvedores para entender por que a falha aconteceu.
3. **Desenvolvimento da Solução:** Os squads de Front/Back trabalham junto com o time de segurança para corrigir o bug de forma rápida e segura.
4. **Aplicação do Patch:** A correção é testada e aplicada diretamente na branch `develop`.
